Dimensional model

Star schema (test branch)

Fact at the center. Dimensions use surrogate keys (*_key IDENTITY) plus natural keys. Date and time are split. Click a table for columns.

dim_users DIM
  • user_keyPK
  • user_id (natural)
  • gender, age, income…
  • + metadata
dim_card DIM
  • card_keyPK
  • card_id (natural)
  • brand, type, limit…
  • + metadata
fact_transactions FACT
  • transaction_id
  • date_key · time_key
  • user_key · card_key
  • merchant_key · amount
dim_date DIM
  • date_keyPK
  • full_date, year, quarter
  • month, day, day_type
  • week_of_year
dim_time DIM
  • time_keyPK
  • hour, minute, block
  • am_pm, time_of_day
  • minute_of_day
dim_merchant DIM
  • merchant_keyPK
  • merchant_id (natural)
  • city, state, zip
  • mcc + description

Reliability & performance

Data quality, indexes & partitioning

From the SQL scripts on the test branch.

✓ Data quality checks

  • Duplicate keys
  • NULLs in critical columns
  • Negative / outlier amounts
  • Future-dated transactions
  • Unexpected entry methods
  • Error-type frequency
  • Referential integrity (orphan FKs)
  • dw_load_timestamp freshness

Scripts under sql/*_data_quality_check.sql

⚡ Indexing & partitioning

  • Clustered columnstore on fact_transactions
  • PK on all dimension surrogate keys
  • Partition function by year (2017–2019 + future)
  • Filegroups FG_2017 … FG_FUTURE
  • Scheme mapped to filegroups
  • Fact: ON scheme_partition_by_year (transaction_date)
